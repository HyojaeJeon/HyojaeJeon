# 가맹점 데이터 연동 계획

> 작성일: 2026-04-13
> 상태: 계획 단계

## 1. 현황 분석

### 1.1 현재 Platform DB (CentralApi)

가맹점 관련 테이블은 **BrandHQ 트리 + MealMerchantEnrollment** 구조:

```
BrandProfile          → 브랜드 본사 (이름, 대리점 FK)
  └─ Branch           → 지점 (이름, 주소, branchType, 영업시간 JSON)
MealMerchantEnrollment → 식권 가맹 등록 (brandHqId 1:1, loopType, 수수료, 정산계좌)
```

**부족한 부분:**
- 가맹점 상세 정보 (전화번호, 위치 좌표, 요리 카테고리, 배달비, 최소주문금액, 평점)
- 메뉴/메뉴카테고리/메뉴옵션 (BrandMenuCategory/BrandMenuItem은 POS 카탈로그 전용)
- 메뉴 이미지 (프로필 이미지, 메뉴 아이템 이미지)
- 가맹점 이미지 (로고, 배너, 인테리어/외관 사진)

### 1.2 외부 데이터 소스

| 소스 | 위치 | 규모 | 설명 |
|------|------|------|------|
| **fooding/server DB** | MySQL (로컬) | ~1,900개 가맹점 | Sequelize 모델 기반. Stores, MenuCategories, MenuItems, MenuOptionGroups, MenuOptions, StoreImages |
| **delivery-k-croll** | JSON 파일 (5.1GB) | 1,943개 (19개 도시) | 크롤링 원본. store_info.json, menu.json, images/, raw_api_data.json |

### 1.3 이미지 현황

크롤링 데이터의 이미지는 **Cloudflare CDN** URL로 저장:
- 가맹점 썸네일: `https://d3i25w97yl4le9.cloudfront.net/thumb/shops/[hash].jpeg`
- 메뉴 아이템: `https://d3i25w97yl4le9.cloudfront.net/shops/[id]/products/thumbs/[hash].png`
- 로컬 캐시: `data/[city]/[store]/images/menu_[seq]_[name].[ext]`

## 2. DB 스키마 확장 계획

### 2.1 전략: 기존 BrandProfile/Branch 확장 vs 신규 테이블

**선택: 기존 테이블 확장 + 부족한 부분만 신규 생성**

이유:
- `BrandProfile`은 이미 브랜드 본사 역할 (가맹점 본사 = BrandProfile)
- `Branch`는 이미 지점 역할 (가맹점 지점 = Branch)
- 메뉴는 `BrandMenuCategory` / `BrandMenuItem`이 이미 존재
- 신규 필요: 지점 상세 (좌표, 전화번호, 배달정보), 메뉴 이미지, 가맹점 이미지, 메뉴 옵션

### 2.2 Branch 테이블 확장 (기존 필드 + 신규 필드)

```prisma
model Branch {
  // ── 기존 필드 ──
  id, brandHQId, distributorId, branchCode, branchName, branchType
  countryCode, regionCode, addressLine1, addressLine2, postalCode
  timeZoneCode, defaultLanguageCode, businessHoursJson, status
  openingDate, closingDate

  // ── 신규 추가 필드 ──
  phone             String?   @db.VarChar(30)     // E.164 전화번호
  latitude          Decimal?  @db.Decimal(10, 8)  // 위도
  longitude         Decimal?  @db.Decimal(11, 8)  // 경도
  cuisineType       String?   @db.VarChar(100)    // 요리 카테고리 (chicken, noodles 등)
  logoUrl           String?   @db.VarChar(500)    // 로고 이미지 URL
  profileImageUrl   String?   @db.VarChar(500)    // 대표 이미지 URL
  bannerImageUrl    String?   @db.VarChar(500)    // 배너 이미지 URL
  deliveryFeeVnd    Int?                          // 배달비 (VND)
  minOrderAmountVnd Int?                          // 최소 주문 금액 (VND)
  rating            Decimal?  @db.Decimal(2, 1)   // 평점 0.0~5.0
  reviewCount       Int       @default(0)         // 리뷰 수
  description       String?   @db.Text            // 가맹점 소개
  descriptionKo     String?   @db.Text
  descriptionEn     String?   @db.Text
  paymentMethodsJson Json?                        // 결제 수단 JSON
  externalSourceId  String?   @db.VarChar(100)    // 외부 시스템 원본 ID (fooding store id)
}
```

### 2.3 BrandMenuItem 확장

```prisma
model BrandMenuItem {
  // ── 기존 필드 ──

  isAvailable       Boolean   @default(true)
```

### 2.4 신규 테이블: BrandMenuOptionGroup + BrandMenuOption

```prisma
model BrandMenuOptionGroup {
  id            String   @id @default(uuid()) @db.Uuid
  menuItemId    String   @db.Uuid
  name          String   @db.VarChar(200)
  nameKo        String?  @db.VarChar(200)
  nameEn        String?  @db.VarChar(200)
  isRequired    Boolean  @default(false)
  maxSelections Int?                          // null = 무제한
  displayOrder  Int      @default(0)
  createdAt     DateTime @default(now()) @db.Timestamptz()
  updatedAt     DateTime @updatedAt @db.Timestamptz()

  menuItem BrandMenuItem   @relation(fields: [menuItemId], references: [id])
  options  BrandMenuOption[]

  @@index([menuItemId, displayOrder])
}

model BrandMenuOption {
  id           String   @id @default(uuid()) @db.Uuid
  groupId      String   @db.Uuid
  name         String   @db.VarChar(200)
  nameKo       String?  @db.VarChar(200)
  nameEn       String?  @db.VarChar(200)
  priceVnd     BigInt   @default(0)
  isDefault    Boolean  @default(false)
  isAvailable  Boolean  @default(true)
  displayOrder Int      @default(0)
  createdAt    DateTime @default(now()) @db.Timestamptz()
  updatedAt    DateTime @updatedAt @db.Timestamptz()

  group BrandMenuOptionGroup @relation(fields: [groupId], references: [id])

  @@index([groupId, displayOrder])
}
```

### 2.5 신규 테이블: BranchImage

```prisma
model BranchImage {
  id           String   @id @default(uuid()) @db.Uuid
  branchId     String   @db.Uuid
  imageType    String   @db.VarChar(30) // LOGO | PROFILE | BANNER | MENU | INTERIOR | EXTERIOR | FOOD
  url          String   @db.VarChar(500)
  displayOrder Int      @default(0)
  isPrimary    Boolean  @default(false)
  createdAt    DateTime @default(now()) @db.Timestamptz()
  updatedAt    DateTime @updatedAt @db.Timestamptz()

  branch Branch @relation(fields: [branchId], references: [id])

  @@index([branchId, imageType])
}
```

## 4. 이미지 처리 전략

### 4.1 접근 방식: Cloudflare URL 직접 참조

크롤링 데이터의 이미지는 이미 Cloudflare CDN에 업로드되어 있음.

**단기 (Phase 1 — 시드):**
- Cloudflare URL을 DB에 그대로 저장 (`https://d3i25w97yl4le9.cloudfront.net/...`)
- 추가 업로드/복사 없음
- Portal/앱에서 `<img src={url}>` 직접 렌더링

**중기 (Phase 2 — 자체 CDN 이관):**
- 자체 Cloudflare Images 계정 또는 S3 + CloudFront로 이관
- 이관 스크립트: 기존 URL 다운로드 → 자체 CDN 업로드 → DB URL 업데이트
- 로컬 캐시 (`data/[city]/[store]/images/`)를 벌크 업로드 소스로 활용

**장기 (Phase 3 — 이미지 서비스):**
- 이미지 업로드 API (가맹점 셀프 서비스)
- 리사이징/최적화 파이프라인 (Sharp/Imgproxy)
- 메뉴 이미지 AI 자동 분류

### 4.2 이미지 URL 필드 규칙

- 모든 이미지 URL 필드는 `VarChar(500)` — 절대 URL 저장
- `null` = 이미지 없음, 프론트엔드에서 fallback placeholder 표시
- 상대 경로/로컬 파일 경로 저장 금지
- URL 유효성은 저장 시 검증하지 않음 (CDN 장애 대비)

## 5. 시드 데이터 주입 계획

### 5.1 데이터 소스 우선순위

1. **fooding/server MySQL** — 정형화된 Sequelize 모델. 관계 데이터 완전.
2. **delivery-k-croll JSON** — 원본 크롤링. fooding DB에 없는 추가 메타데이터 보유.

**전략:** fooding MySQL을 primary로 읽고, crawl JSON을 보조 참조로 사용.

### 5.2 시드 스크립트 구조

```
SuperAdmin/CentralApi/prisma/seedMerchants.ts
  ├── connectFoodingDb()     ← fooding MySQL 직접 연결 (읽기 전용)
  ├── seedBrandProfiles()    ← Stores → BrandProfile + Branch 변환
  ├── seedMenuData()         ← MenuCategories/Items/Options → 카탈로그 변환
  ├── seedImages()           ← StoreImages → BranchImage 변환
  ├── seedEnrollments()      ← MealMerchantEnrollment 생성 (loopType 기본 CLOSED_LOOP)
  └── report()               ← 결과 리포트
```

### 5.3 실행 순서

1. **Prisma migration** — Branch/BrandMenuItem 확장 + 신규 테이블 생성
2. **seedMerchants.ts 실행** — fooding DB → Platform DB 변환 주입
3. **검증** — Portal merchants 화면에서 데이터 확인

### 5.4 멱등성

- `externalSourceId` (fooding store id) 기준 upsert
- 중복 실행 시 기존 데이터 업데이트 (파괴 아님)
- 메뉴/옵션은 branchCode + itemCode 기준 upsert

## 6. 주소 파싱 전략

fooding의 `address` 필드는 자유 형식 문자열:
```
"Số 42 Trần Phú, Hải Châu, Đà Nẵng"
"199/6 Nguyễn Văn Hưởng, Thảo Điền, Quận 2, TP. Hồ Chí Minh"
```

**파싱 방법:**
- 크롤링 데이터의 도시 폴더명 (`da-nang`, `ho-chi-minh`) → `regionCode` 매핑
- `countryCode` = `'VN'` (모두 베트남)
- 전체 주소 → `addressLine1`에 저장
- 구/군 파싱은 Phase 2에서 정규식 + 베트남 행정구역 사전 기반

## 7. 리스크 및 고려사항

| 리스크 | 대응 |
|--------|------|
| Cloudflare URL 만료/차단 | Phase 2에서 자체 CDN 이관. 단기적으로 로컬 캐시 백업 보유 |
| fooding DB 스키마 변경 | seedMerchants.ts에 버전 체크 + 스키마 검증 |
| 1,900개 동시 insert 성능 | 100개씩 배치 upsert + 트랜잭션 |
| 다국어 필드 매핑 불일치 | fooding은 name/nameKo/nameEn 3벌, Platform도 동일 패턴 |
| 메뉴 가격 단위 | fooding은 VND INT, Platform BrandMenuItem은 BigInt — 변환 필요 없음 |
| 주소 정규화 | Phase 1은 raw 저장, Phase 2에서 구조화 |
