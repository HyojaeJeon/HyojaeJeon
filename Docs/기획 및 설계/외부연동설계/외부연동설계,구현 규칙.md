# 외부 연동 설계/구현 규칙

> **적용 대상**: ExternalBridge 하위 모든 모듈 (Fooding, KMedical, PaymentGateways)
> **목적**: 외부 서비스가 늘어나도 동일한 패턴으로 안전하게 연동

---

## 규칙 1. 단방향 데이터 흐름 (Dependency Rule)

외부 서비스는 **절대로 UI나 DB를 직접 제어하지 않는다**. 반드시 Manager(비즈니스 로직)를 거쳐야 한다.

**올바른 흐름:**

```
[수신] ExternalBridge가 MQTT/API 수신 → JSON 파싱
         ↓
[의뢰] OrderMgr->CreateOrder(data) 호출 (비즈니스 로직)
         ↓
[통지] InternalBridge를 통해 UI에 이벤트 전송
         ↓
[갱신] Next.js가 이벤트를 받고 Redux 상태 업데이트
```

**금지 사항:**
- ExternalBridge에서 SQL INSERT 직접 실행
- ExternalBridge에서 CEF JavaScript 직접 호출
- ExternalBridge에서 UI 컨트롤 직접 조작

---

## 규칙 2. 스레드 안전 보장 (Thread Safety)

MQTT, HTTP 콜백은 **별도 스레드**에서 동작한다. UI/DB 객체를 직접 참조하면 크래시 발생.

**원칙:**
- ExternalBridge 콜백 내부에서 UI 객체, DB 연결 객체를 직접 참조 금지
- 모든 데이터는 JSON 또는 구조체에 담아 **메인 UI 스레드로 PostMessage** 전송
- 메인 스레드에서 안전하게 Manager 호출 → InternalBridge → UI 갱신

**CEF 주의사항:**
- CEF Browser API는 반드시 **UI 스레드(TID_UI)**에서 호출
- MQTT 스레드에서 `ExecuteJavaScript()` 직접 호출 금지 → PostMessage로 위임

---

## 규칙 3. 인터페이스 표준화 (Standardized API)

모든 외부 연동은 **동일한 JSON 메시지 규격**을 사용한다.

### 요청 (외부 → POS)

```json
{
  "cmd": "ORDER_NEW",
  "payload": { ... },
  "requestId": "uuid-xxx",
  "timestamp": "2026-03-31T12:00:00+07:00"
}
```

### 응답 (POS → 외부)

```json
{
  "status": "SUCCESS",
  "code": 200,
  "data": { ... },
  "requestId": "uuid-xxx"
}
```

### 에러

```json
{
  "status": "ERROR",
  "code": 400,
  "msg": "Invalid Item",
  "requestId": "uuid-xxx"
}
```

**새 외부 서비스 추가 시:**
1. `ExternalBridge/` 아래 폴더 생성 (예: `KMedical/`)
2. 위 JSON 규격을 준수하는 수신/발신 모듈 구현
3. Manager 호출은 반드시 메인 스레드에서 (규칙 2)

---

## 규칙 4. 비동기 통신 보호 (중복 요청 차단)

### 4.1 ExternalBridge (외부 수신 측)

- 각 서비스(Fooding, ZaloPay 등)마다 `m_isWaitingResponse` 플래그 유지
- 응답이 오기 전까지 동일 `requestId`를 가진 요청은 무시
- 타임아웃 설정 (기본 60초) — 초과 시 자동 해제

### 4.2 InternalBridge (UI 요청 측)

- 결제, 주문 등 부수효과가 있는 Action은 `std::lock_guard` 또는 `std::atomic<bool>`로 이중 진입 차단
- 이미 처리 중인 Action에 대한 중복 cefQuery는 즉시 에러 응답 반환

### 4.3 UI (Next.js)

- 결제/인쇄 등 버튼은 클릭 즉시 `disabled` 처리 (C++ 응답 대기 전에 선제 차단)
- Redux `createAsyncThunk`의 `pending` 상태에서 **Global Overlay(Spinner)** 표시
- 모든 비동기 Action은 `IDLE → PROCESSING → SUCCESS/FAILED` 상태 머신 필수

### 4.4 방어 계층 요약

```
[1차] UI 버튼 disabled + Spinner     ← 사용자 연타 즉시 차단
[2차] InternalBridge Mutex/Lock      ← UI 방어 우회 시 C++에서 차단
[3차] ExternalBridge 중복 요청 무시   ← 외부 서비스 중복 전송 방지
```
