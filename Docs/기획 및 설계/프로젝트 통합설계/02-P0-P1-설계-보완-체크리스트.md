# P0/P1 설계 보완 체크리스트

> 대상 문서: `01-CEF-NextJS-전환-계획서.md`
> 목적: 운영 반영 전 필수 보완 항목을 우선순위 기준으로 점검

---

## 사용 방법

- `P0`: 미완료 상태로 운영 반영 금지
- `P1`: 파일럿 운영 전까지 완료 권장
- 각 항목은 구현 완료뿐 아니라 **검증 근거**까지 있어야 완료로 판단

---

## P0

### 1. 계층 경계

- [ ] `PosRequestActions`가 직접 SQL/Manager 조합 로직을 수행하지 않고 `UseCases`만 호출한다
- [ ] `ExternalBridge`가 직접 SQL을 수행하지 않는다
- [ ] `ExternalBridge`가 직접 `PosRealTimeSender`를 호출하지 않는다
- [ ] UI 송신은 `PosRealTimeSender` 단일 경로만 사용한다

### 2. 멱등성 / 중복 처리

- [ ] 결제 요청에 `requestId`, `idempotencyKey`가 필수 적용된다
- [ ] 주문 생성/수정/취소에도 `requestId` 추적이 적용된다
- [ ] 영속 Ledger 테이블에 `RECEIVED/PROCESSING/SUCCEEDED/FAILED/COMPENSATED` 상태가 기록된다
- [ ] 동일 `idempotencyKey` 재수신 시 신규 실행이 아니라 기존 결과를 재반환한다

### 3. 트랜잭션 / 정합성

- [ ] DB 영속화 완료 전 외부 ACK를 보내지 않는다
- [ ] DB 영속화 완료 전 UI 상태를 갱신하지 않는다
- [ ] 인쇄/장치 실패와 DB 저장 실패를 구분하는 정책이 문서화되어 있다
- [ ] 하나의 use case는 하나의 `UseCase` 단위에서 종료된다

### 4. 장애 복구

- [ ] 프로세스 재시작 시 미완료 `PROCESSING` 작업 재검사 절차가 구현되어 있다
- [ ] 미완료 결제 재조회 규칙이 문서화되어 있다
- [ ] 테이블/주문/배달 데이터는 DB 기준으로 재수화 가능하다
- [ ] 외부 ACK 미전송 건의 재전송 절차가 있다

### 5. 운영 안전장치

- [ ] 화면 단위 feature flag가 존재한다
- [ ] 핵심 3개 화면에 MFC fallback 경로가 존재한다
- [ ] 운영 롤백 조건이 문서화되어 있다
- [ ] 파일럿 매장 전개 순서가 정의되어 있다

## P1

### 1. 브라우저 / 런타임

- [ ] `CefBrowser` 단일 인스턴스 전략이 구현 설계에 반영되어 있다
- [ ] `root_cache_path`, `cache_path`가 명시적으로 설정된다
- [ ] 세션 쿠키 / localStorage 지속 정책이 문서화되어 있다
- [ ] remote debugging / devtools 정책이 운영과 개발 환경별로 구분된다

### 2. 성능 / 메모리

- [ ] x86 메모리 한계치와 허용 RSS 기준이 정의되어 있다
- [ ] 장시간 soak test 시나리오가 존재한다
- [ ] 화면 전환 시간, 첫 로딩 시간, 결제 완료 시간의 목표치가 있다
- [ ] x86 기준 미달 시 x64 전환 게이트가 문서화되어 있다

### 3. 계약 / 인터페이스

- [ ] 메시지 Envelope 표준이 모든 채널에 공통 적용된다
- [ ] `v`, `requestId`, `timestamp`, `idempotencyKey` 필드 사용 규칙이 고정되어 있다
- [ ] Bridge 요청/응답 예제가 문서화되어 있다
- [ ] `VERSION_MISMATCH` 처리 UX가 정의되어 있다

### 4. 관측성

- [ ] 모든 로그에 `requestId` 체인이 포함된다
- [ ] 장치 로그, 브릿지 로그, 업무 로그가 분리된다
- [ ] 장애 시 어떤 로그를 우선 확인해야 하는지 운영 가이드가 있다
- [ ] 외부 결제/VAN/MQTT 응답 추적 키가 문서화되어 있다

### 5. 품질 보증

- [ ] Bridge contract test가 자동화되어 있다
- [ ] `UseCase` 단위 테스트가 존재한다
- [ ] 강제 종료 후 복구 테스트가 존재한다
- [ ] MFC 결과와 신 UI 결과 동등성 비교 시나리오가 존재한다

### 6. 배포 / 정적 빌드

- [ ] Next.js는 `output: 'export'` 기준으로 빌드된다
- [ ] 정적 export에서 금지되는 기능 목록이 공유되어 있다
- [ ] `app://pos/` scheme handler가 정적 파일 라우팅 규칙을 제공한다
- [ ] UI/CEF/리소스 버전 동기화 규칙이 있다
